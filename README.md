# 🦷 DB Live Stock Tracker
### A Real-Time Dental Inventory Monitoring & Stock Alert System

**React | JavaScript | Firebase Firestore | Vite | Vercel**

## 📌 Project Overview

DB Live Stock Tracker is a web-based inventory management application developed to improve stock visibility, streamline inventory monitoring, and reduce the risk of supply shortages in a high-volume dental clinic.

The project originated from firsthand observations of inventory inefficiencies while working as a Senior Dental Assistant at Dental Boutique Sydney.

Rather than relying exclusively on reactive stock replenishment and informal communication between staff, I wanted to explore how a shared, real-time digital system could improve inventory visibility and support more proactive stock management.

The application was designed around the workflows of dental assistants, allowing staff to monitor stock levels and flag supplies requiring replenishment across treatment rooms.

🔗 **[View Live Application](https://db-live-stock-alert-system.vercel.app/)**

## 🎯 The Problem

Managing inventory across a large dental clinic presents several operational challenges:

- **Limited stock visibility:** Staff may not know which treatment rooms are running low on supplies.
- **Reactive replenishment:** Stock shortages are often discovered only when materials are needed.
- **Inventory redistribution:** Staff may borrow materials from other rooms without a centralised record.
- **Communication gaps:** Stock requests can become fragmented across staff and shifts.
- **Operational inefficiencies:** Time spent searching for supplies, communicating shortages, and replenishing rooms can disrupt clinical workflows.

These observations highlighted an opportunity to create a more transparent, accessible and standardised inventory monitoring system.

## 💡 The Solution

I developed a shared inventory tracking application focused on making stock shortages visible and actionable.

### Core Features

**1. Real-Time Stock Monitoring**
- Shared stock information across users.
- Firebase Firestore integration for synchronising inventory updates.
- Centralised visibility of reported stock shortages.

**2. Low-Stock Alert System**
- Allows dental assistants to flag items requiring replenishment.
- Makes stock shortages visible to other team members.
- Supports more proactive inventory monitoring.

**3. Room-Based Stock Auditing**
- Supports stock checks at the treatment-room level.
- Helps staff identify missing or depleted supplies.
- Encourages more consistent room inventory practices.

**4. Mobile-Friendly Access**
- Web-based interface accessible from compatible devices.
- Designed to support practical use within a busy clinical environment.
- Supports adding the application to a device's home screen.

## 🧠 Development Approach

### 1. Problem Identification

Observed recurring operational inefficiencies associated with stock shortages, treatment-room replenishment and communication between staff.

### 2. Workflow Analysis

Considered how dental assistants interact with stock throughout the working day, including identifying shortages, requesting supplies and auditing rooms.

### 3. Solution Design

Developed an application centred on accessibility, shared visibility and simple stock-reporting workflows.

### 4. Implementation & Deployment

Built a React-based web application using Firebase Firestore for shared data storage and deployed it through Vercel.

### 5. Feedback & Iteration

Gathered feedback from clinical staff and leadership to evaluate usability, identify workflow friction and refine features.

This iterative process reinforced the importance of designing software around actual user behaviour rather than assumptions about how a system should operate.

## 📈 Outcomes & Learnings

The project received positive feedback from clinical staff and management and created opportunities for further discussions around inventory visibility and workflow improvement.

Key learnings included:

- Translating operational problems into software requirements.
- Designing features around real clinical workflows.
- Understanding the relationship between frontend interfaces and cloud-hosted data.
- Considering user adoption and behavioural change during software implementation.
- Incorporating stakeholder feedback into product decisions.
- Recognising the importance of usability, communication and iteration alongside technical implementation.

**A key insight:** Building a functional application is only one component of solving an operational problem. Its real value depends on whether users understand it, adopt it, and integrate it into their workflows.
